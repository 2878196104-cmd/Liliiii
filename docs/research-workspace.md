# 专题研究工作台

导航顺序：行业趋势 → 阅读竞品 → 结论证据 ｜ 专题研究 → 信息源库。
前面三页属于常规竞品阅读。专题研究使用独立内容池，不复用月报拆解页面。

## 信息扩充

- `config/research-sources.json` 登记17个专题入口（包括同一媒体的多个专题入口，不等于17家媒体）。
- `config/research-cases.json` 保存11条人工核对来源的摘要，涵盖2024年10月至2026年3月的案例。
- 官网入口、媒体报道、专业机构与展会资料分别标识；`manual` 只登记供人工核验，不声称已经自动采集。
- 页面事实摘要不等于营销效果认证；借鉴线索为编辑推论，明确注明边界。不是 Jev 生成结果。
- 近两年按当前日期减两年动态计算，不把采集日期当作事件日期。

## 沿用现有数据结构

- 来源发现配置里用 `pools`；旧来源默认 `competitor`。
- 私有资料保存在 `raw_documents.raw_payload.pools`，重复来源合并时并集两个池，不复制文章。
- 自动采集优先登记专题入口、录入首批摘要，再采集专题索引；原有来源继续运行。
- 初次录入的摘要为 `needs_review`，不会自动修改或发布数据库中的事件。
- 后台切换信息池后，采集、人工审核、统计、批量 Jev 和预览同步切换。
- 事件复用已有 `created_by` 字段：`admin-research` 为专题；`admin-both` 为双池；其余为常规。无需新的迁移。
- 后台发布前仍需人工确认。研究事件不会进入常规阅读或结论统计；双池事件可以进入两边。
- 原文 URL 以 `原文：` 前缀保存在已有 `actions` 数组，公开映射提取链接后移除前缀项。

## 草稿边界

主题、范围、营销任务、时间选项真实筛选已收录资料，不是实时全网搜索。
方案区只按任务聚合用户主动选中的材料，不调用模型或自动输出已验证策略。
选择和笔记以主题为键保存在当前浏览器，明确不跨设备同步，可导出 Markdown 草稿。
更换筛选不清空已选资料；更换主题切换对应草稿。浏览器禁止存储时提示导出。

## 运维

现有 GitHub Actions 读取新增配置。无需新增 API 密钥或重新部署 Jev。
来源状态以后台最近运行时间与实际资料条数为准；`last_collected_at` 只表示采集运行完成，不保证发现新资料。
后续应增补独立媒体和专业报告，避免首批营销案例过度集中于单一出版社。
