# 专题研究工作流 v1：睡眠品类品牌节 MVP

本次截至 2026-10-07，事件研究范围 2024-10-07 至 2026-10-07。人工策展样本，不是穷尽检索，不是 Jev 自动生成。已有案例16条（包含跨界灵感），不等于16条直接竞品活动；来源登记数量不能替代案例覆盖。

## 1. 先问决策，不先选案例

每个专题填写：主题、目标人群、业务目标、主推品类、品牌/平台、时间、预算、渠道、可用服务与一条决策问题。未知项必须列为假设，不由模型补全。

本次问题：如何让床垫、枕头、床品与智能床成为值得参与的品牌节，而不是多个促销会场？暂假设具有多品类与可用体验场地，尚未得到用户确认。

## 3. 证据入库结构

沿用 research-cases.json：id、date、date_basis、brand、title、products、scope、tasks、kind、url、source、summary、idea、limits、tags。summary只写可核对的事实；idea明确是推断；limits写缺口。新增专题可沿用结构，不强行使用睡眠品类选项。

多个报道的同一活动共享case id；多活动共用一篇综合报告时也不能只按URL抹除。当前页面仍用URL初步去重，后续需引入事件实体去重；不能声称已解决所有语义重复。

## 4. 深挖与判断结构

sleep-research.json是首份结构化研究稿：决策问题、假设、时间窗口、覆盖缺口、insights、deep_cases、workflow。

每个重点案例重建：问题→产品证明→内容分发→体验→成交→反馈。缺证据的环节显式留空。判断必须具有 evidence_ids、reasoning、direction、conditions、counter、test。重点深挖机制不同的两案，不把各品牌都塞进相同结论。

## 5. 展示和验收

首页只展示三条暂时判断，展开查看证据、反例、条件与验证。资料默认折叠，跨界另列。切换主题不展示睡眠结论；过滤后至少两个相关证据仍在当前结果中，才展示对应判断。另保留研究稿草稿与原文入口。

验收不是条数，而是用户能否提出一个具体方向，并说明证据、迁移条件和风险。先确认业务简报，再做小规模材料理解/预约试验，用实际反馈修订。没有基线和成本数据，不给ROI承诺。

## 实现边界

research-insights.js目前只加载睡眠人工研究稿；新专题显示工作流和未研究提示，尚未实现自动生成新的研究稿、全网搜索、跨设备研究稿同步。已有Jev体系本轮未改动，也未声称本研究由Jev完成。
